A API expõe dois endpoints, ambos somente leitura:

| Método | Rota | Descrição |
|---|---|---|
| `GET` | `/appointments` | Lista agendamentos, com filtros e paginação |
| `GET` | `/appointments/{id}` | Detalhe de um agendamento específico |

Nenhuma rota tem barra final. Na referência da API gerada a partir do OpenAPI, o parâmetro de rota da URL de detalhe aparece como `public_id` — é o mesmo valor do campo `id` no corpo da resposta, o identificador público do agendamento (veja [Identificador](#identificador) abaixo).

## Listar agendamentos

```bash
curl -H "Authorization: Bearer bd_live_xxxxxxxx.yyyy" \
  "https://api.bydoctor.com.br/api/public/v1/appointments?start_date=2026-08-01&end_date=2026-08-31&status=confirmed"
```

### Filtros

| Parâmetro | Tipo | Descrição |
|---|---|---|
| `start_date` | `date` | Início da janela (inclusivo). Combinado com `end_date`, a janela não pode exceder **92 dias**. |
| `end_date` | `date` | Fim da janela (inclusivo). |
| `status` | `string` | Um de: `requested`, `scheduled`, `confirmed`, `checked_in`, `completed`, `no_show`, `cancelled`. |
| `professional_id` | `integer` | Filtra pelo profissional. |
| `patient_id` | `integer` | Filtra pelo paciente. |
| `room_id` | `integer` | Filtra pela sala. |
| `modality` | `string` | `in_person` ou `telehealth`. |
| `updated_since` | `datetime` (ISO 8601) | Retorna apenas agendamentos atualizados a partir deste instante. Veja [Sincronização](/sincronizacao). |
| `cursor` | `string` | Cursor de paginação — use o valor devolvido em `next`, não construa manualmente. |
| `page_size` | `integer` | Itens por página. Padrão **50**, máximo **100**. |

### Paginação por cursor

A paginação é por cursor, não por número de página. A resposta traz `next` (e `previous`) como URLs prontas — siga `next` até que ele venha `null`; não tente calcular offsets ou montar o cursor você mesmo.

```json
{
  "next": "https://api.bydoctor.com.br/api/public/v1/appointments?cursor=cD00ODY%3D&start_date=2026-08-01&end_date=2026-08-31",
  "previous": null,
  "results": [
    {
      "id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
      "status": "confirmed",
      "modality": "in_person",
      "origin": "patient_booking",
      "start_at": "2026-08-10T14:00:00-03:00",
      "end_at": "2026-08-10T14:30:00-03:00",
      "created_at": "2026-08-01T09:12:00-03:00",
      "updated_at": "2026-08-05T08:00:00-03:00",
      "patient": {
        "id": 981,
        "name": "Maria Silva",
        "phone": "+5511999998888"
      },
      "professional": {
        "id": 12,
        "name": "Dr. João Souza",
        "specialty": "Cardiologia"
      },
      "room": {
        "id": 3,
        "name": "Sala 2"
      }
    }
  ]
}
```

`patient`, `professional` e `room` podem vir `null` — por exemplo, uma teleconsulta não tem sala associada.

`patient.phone` é o texto cadastrado pela clínica, sem normalização; não há garantia de formato E.164 — `(11) 99999-8888` é tão provável quanto `+5511999998888`.

`origin` indica como o agendamento foi criado: `staff` (equipe da clínica) ou `patient_booking` (agendamento online feito pelo paciente).

## Buscar um agendamento

```bash
curl -H "Authorization: Bearer bd_live_xxxxxxxx.yyyy" \
  "https://api.bydoctor.com.br/api/public/v1/appointments/3fa85f64-5717-4562-b3fc-2c963f66afa6"
```

Devolve o mesmo objeto de agendamento mostrado acima. Um `id` inexistente ou de outra clínica responde `404 Not Found`.

## Erros

| Código | Quando acontece |
|---|---|
| `400 Bad Request` | Filtro inválido — `status` desconhecido, `start_date` posterior a `end_date`, ou janela maior que 92 dias. |
| `401 Unauthorized` | Chave ausente, revogada ou expirada. |
| `403 Forbidden` | Chave válida, mas sem o escopo `appointments:read`. |
| `429 Too Many Requests` | Limite de requisições excedido — veja [Autenticação](/autenticacao) para os limites e o cabeçalho `Retry-After`. |

## Identificador

O `id` de um agendamento é um **UUID** — é o identificador público do agendamento e o único valor aceito na URL de detalhe. A chave primária interna (inteira) do agendamento nunca é exposta; armazene o UUID como chave estrangeira do agendamento no seu sistema — ele é estável entre chamadas e entre eventos de webhook.

Isso não vale para os objetos aninhados: `patient.id`, `professional.id` e `room.id` **são** as chaves primárias internas (inteiras) do paciente, do profissional e da sala, expostas de propósito porque são os mesmos valores aceitos pelos filtros `patient_id`, `professional_id` e `room_id`. Se você pretende filtrar por eles depois, guarde esses valores também.
